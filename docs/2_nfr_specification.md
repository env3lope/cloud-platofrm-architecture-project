# 2. Специфікація нефункціональних вимог (NFR)

| № | Категорія якості | Підхарактеристика | Конкретизована нефункціональна вимога | Кількісний індикатор / метрика |
|---:|---|---|---|---|
| NFR-01 | Performance Efficiency (Продуктивність) | Capacity (Ємність) | Система повинна підтримувати пікове навантаження під час створення замовлень без масових помилок сервера. | До 3 000 запитів на секунду; частка відповідей HTTP 5xx ≤ 0,1% протягом 15-хвилинного тесту навантаження. |
| NFR-02 | Reliability (Надійність) | Availability (Доступність) | Платформа повинна залишатися доступною для користувачів протягом усього року, за винятком допустимого простою. | Місячна доступність ≥ 99,9%; плановий простій включається до розрахунку, якщо це передбачено прийнятою політикою SLA. |
| NFR-03 | Security (Безпека) | Confidentiality (Конфіденційність) | Персональні дані та інші чутливі дані повинні бути захищені під час зберігання й передавання. | Шифрування даних у сховищах із використанням AES-256; передавання даних через TLS 1.3. |
| NFR-04 | Maintainability (Підтримуваність) | Testability (Тестованість) | Бізнес-логіка платформи повинна бути організована так, щоб її можна було перевіряти автоматизованими модульними тестами. | Покриття Domain та Use Cases модульними тестами ≥ 80% за результатами звіту інструмента вимірювання покриття. |
| NFR-05 | Flexibility (Гнучкість) | Scalability (Масштабованість) | Система повинна автоматично збільшувати кількість екземплярів сервісів у разі тривалого зростання навантаження. | Horizontal Pod Autoscaler (HPA) повинен ініціювати масштабування, коли середнє використання CPU перевищує 70% протягом 2 хвилин. |
