## QAS-1. Продуктивність під час пікового навантаження

- **Source (Джерело):** Покупці маркетплейсу, які одночасно виконують пошук товарів під час масового розпродажу.
- **Stimulus (Імпульс):** Надходження великої кількості HTTP GET-запитів для пошуку товарів за назвою, категорією та іншими параметрами.
- **Environment (Середовище):** Пікове навантаження (Peak Load), що становить 1 000 запитів на секунду до сервісу каталогу.
- **Artifact (Артефакт):** API Gateway, сервіс каталогу товарів (Catalog Service) та система зберігання даних каталогу.
- **Response (Реакція):** Система приймає запити, виконує пошук товарів, повертає результати клієнтам і реєструє показники продуктивності для подальшого моніторингу.
- **Response Measure (Міра реакції):** 95-й перцентиль часу відповіді (p95) не перевищує 150 мс; частка відповідей HTTP 5xx не перевищує 0,1% протягом 15-хвилинного тесту навантаження.

## QAS-2. Збереження працездатності під час відмови компонента

- **Source (Джерело):** Збій екземпляра сервісу оформлення замовлень або його примусове завершення під час роботи платформи.
- **Stimulus (Імпульс):** Один з екземплярів Order Service перестає відповідати на запити під час обробки замовлень покупців.
- **Environment (Середовище):** Звичайний робочий режим із навантаженням 500 запитів на секунду до сервісу оформлення замовлень.
- **Artifact (Артефакт):** API Gateway, балансувальник навантаження, Order Service та механізм перевірки працездатності екземплярів.
- **Response (Реакція):** Система виявляє несправний екземпляр, припиняє спрямовувати до нього нові запити та перенаправляє їх до справних екземплярів. Незавершені операції перевіряються або безпечно повторюються з використанням механізмів ідемпотентності.
- **Response Measure (Міра реакції):** Виявлення несправного екземпляра та вилучення його з маршрутизації відбувається не довше ніж за 10 секунд; частка невдалих запитів через цей збій не перевищує 1% протягом хвилини після виникнення відмови; відсутні дубльовані замовлення внаслідок повторної обробки запитів.

## QAS-3. Захист даних під час передавання та доступу

- **Source (Джерело):** Зовнішній клієнт або зловмисник, який намагається перехопити дані під час передавання чи отримати несанкціонований доступ до персональних даних покупців.
- **Stimulus (Імпульс):** Надсилання HTTP-запиту без захищеного з'єднання або спроба отримати персональні дані через API без належної автентифікації чи авторизації.
- **Environment (Середовище):** Робоче середовище платформи з активними користувацькими сесіями та доступом до персональних даних і інформації про замовлення.
- **Artifact (Артефакт):** API Gateway, механізм автентифікації та авторизації, сервіси роботи з користувачами й замовленнями, а також сховище даних.
- **Response (Реакція):** Система відхиляє незахищені HTTP-запити, вимагає автентифікації для захищених операцій, перевіряє права доступу до ресурсів і не повертає дані користувачам, які не мають відповідних дозволів. Спроби несанкціонованого доступу реєструються в журналі безпеки.
- **Response Measure (Міра реакції):** 100% HTTP-запитів через публічний інтерфейс мають використовувати HTTPS із TLS 1.3; усі визначені негативні тести доступу до чужих даних повинні завершуватися відмовою; чутливі дані в сховищі шифруються з використанням AES-256; усі тестові спроби несанкціонованого доступу реєструються.

## QAS-4. Виявлення дефектів під час зміни бізнес-логіки

- **Source (Джерело):** Розробник, який змінює бізнес-логіку розрахунку вартості замовлення або резервування товарів.
- **Stimulus (Імпульс):** Внесення змін до коду відповідного модуля та створення запиту на злиття змін до основної гілки репозиторію.
- **Environment (Середовище):** Середовище розробки та CI/CD-конвеєр, у якому автоматично виконуються перевірки коду й модульні тести.
- **Artifact (Артефакт):** Модулі бізнес-логіки, Domain та Use Cases, набір автоматизованих модульних тестів і CI/CD-конвеєр.
- **Response (Реакція):** Система автоматично запускає модульні тести, перевіряє результати їх виконання та вимірює покриття бізнес-логіки. Якщо тести не проходять або покриття не відповідає встановленому порогу, конвеєр позначає перевірку як невдалу.
- **Response Measure (Міра реакції):** Покриття Domain та Use Cases модульними тестами становить не менше 80%; 100% обов'язкових перевірок у CI повинні завершитися успішно для дозволу злиття змін; результати тестування та покриття публікуються протягом 5 хвилин після завершення тестового етапу.

## QAS-5. Автоматичне масштабування під час зростання навантаження

- **Source (Джерело):** Збільшення кількості покупців і запитів до маркетплейсу під час рекламної кампанії або масового розпродажу.
- **Stimulus (Імпульс):** Середнє використання CPU контейнерами певного сервісу перевищує 70% протягом двох хвилин поспіль.
- **Environment (Середовище):** Пікове навантаження в хмарному середовищі з використанням контейнеризації та Kubernetes.
- **Artifact (Артефакт):** Kubernetes Horizontal Pod Autoscaler (HPA), відповідний сервіс маркетплейсу, метрики CPU та інфраструктура кластера.
- **Response (Реакція):** HPA виявляє перевищення порогового значення та збільшує кількість екземплярів сервісу в межах установлених лімітів. Нові екземпляри проходять перевірки готовності, після чого починають отримувати запити через балансувальник навантаження.
- **Response Measure (Міра реакції):** Ініціювання масштабування відбувається після перевищення CPU 70% протягом двох хвилин; нові екземпляри стають готовими до обробки запитів не довше ніж за 60 секунд після початку масштабування; після стабілізації навантаження p95 часу відповіді сервісу каталогу не перевищує 150 мс за навантаження 1 000 RPS, якщо система залишається в межах виділених ресурсів.
